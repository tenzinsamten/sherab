- (decision) Brand name in UI chrome is 'SHERAB' (product/school internal name) with 'v0.1' version tag next to the logo — distinct from the project's working title 'Class Tracker' / 'tib-class'. Adopt 'SHERAB' as the in-app brand wordmark.
- (decision) Visual style: bold, high-contrast, editorial/brutalist system. Huge, heavy, tight-tracked all-caps display type for headings (e.g. 'CLASS TRACKER', 'SIGN IN', 'CLASSES'); numbered section labels (e.g. '01 / ACCESS', '02 / CLASSES', '03 / TEACHERS') as a recurring wayfinding motif; sharp rectangular corners throughout (no border-radius observed on buttons, inputs, or cards); hairline 1px dividers between list rows; generous whitespace on desktop, single-column stack on phone.
- (decision) Color palette (approximate, read from rendered screenshots — not exact computed values): near-black navy (~#0A1330) for header bars/nav/dark CTAs; vivid royal blue (~#2F5FE0) as the primary accent for primary buttons, active nav tab, large stat numbers, and class-code links; white/off-white (#FFFFFF) content background; amber/orange (~#F2A71B) reserved for one-time/warning notices (seen on the admin-bootstrap explainer banner); near-black text on white, white text on navy/blue.
- (decision) Component patterns observed: primary action buttons are solid blue, full-width on phone, rectangular, bold uppercase label; secondary actions are black-outlined buttons with transparent fill (e.g. 'MANAGE TEACHERS'); nav is a horizontal bar on desktop (tabs become pill-less text/solid-blue-active) collapsing to stacked rows on phone; stat tiles use a 2x2 hairline grid with large bold numbers over small uppercase muted labels; data tables use a dark navy header row with white uppercase column labels on desktop, collapsing to stacked hairline-divided rows on phone; class/invite codes are rendered in a tracked, monospace-leaning blue link style.

- (decision) New component: multi-step form header. Same blue panel as other hero sections, but repurposed as a step list (numbered steps, current step bold white text, future steps dimmed/lighter, completed step also dimmed once passed) plus a 'NEXT STORY / STUDENT' kicker label. Secondary 'BACK' outline button appears alongside primary 'CONTINUE' on steps 2+.
- (decision) New state: field-level validation error. Invalid class code shows a red underline on the input plus red inline text below it ('No class has that code. Check it with your teacher.') -- first observed error/validation treatment in this design system, introducing a semantic 'error red' color not previously in the palette.
- (decision) New state: approve/reject action feedback. Clicking APPROVE or REJECT on a request row is immediate (no confirmation dialog), fires an aria-live polite toast-style banner at the top of content ('APPROVED -- {name} was approved...' / 'REJECTED -- {name} was rejected and will not appear on any roster.'), decrements the nav badge count live, and moves the row into a 'DECIDED -- N APPROVED . M REJECTED' section below a divider with a 'CLEAR REJECTED' secondary button; decided rows show a small solid-blue 'APPROVED' chip or a muted gray 'REJECTED' chip (with the rejected student's name rendered in dimmed/muted text).
- (decision) New state: empty requests queue renders a light hairline-bordered box, 'Nothing waiting' heading + 'New registrations for your classes will appear here.' body -- a distinct, softer empty-state treatment than the stat-tile zero-value pattern.
- (assumption) [REVISED ASSUMPTION] Amber is not exclusively a one-time/irreversible-notice color as previously assumed -- the admin dashboard's 'PENDING' stat tile also renders its number in amber, meaning amber's real semantic is broader: 'needs attention / awaiting action', covering both a one-time procedural warning and an outstanding-count call-to-action. DESIGN.md's Do's and Don'ts entry restricting amber to one-time notices should be corrected, not carried forward as still-open.
