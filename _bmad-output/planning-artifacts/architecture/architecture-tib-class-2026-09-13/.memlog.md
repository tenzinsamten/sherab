- (decision) Security model clarified for user: RLS/Security Rules enforce row-level authorization server-side regardless of client tampering (client is always untrusted). But client-computed award logic (badges, streaks) is a distinct, real risk - a tampered client could self-award. Resolves to: RLS/rules gate plain CRUD (attendance, homework CRUD, marking Done); computed/awarded values (badge crossing, streak counts, leaderboard ranking, recurring-instance generation, deletion cascade) must live in server-side functions (Postgres functions/triggers or Edge/Cloud Functions), never trust a client-submitted computed value for these.
