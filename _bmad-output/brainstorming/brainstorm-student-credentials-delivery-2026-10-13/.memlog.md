- (direction) Problem: username and code are visible only to the admin, so parents or students must come to the admin for credentials
- (idea) Show the username and code during registration
- (idea) Send an email with the credentials when the admin confirms the student
- (decision) Stance: Facilitator. Batch: Build on What Works
- (technique) started Build on What Works
- (insight) What already works: the registration moment, where the person gets what they need without asking anyone
- (insight) Today after registering, the student sees a message that they will be approved, but gets no way to log in
- (idea) Show the username and code right on the post-registration confirmation screen
- (idea) Student can log in to their account immediately while approval is still pending
- (insight) What already works and should be copied: the parent flow, where the parent can log in while approval is pending
- (idea) A logged-in pending student sees only a pending approval message, nothing else
- (idea) On approval, send an email containing the same username and code, so the family still has them after closing the registration screen
- (idea) The approval email with the student's username and code goes to the parent's email address
- (idea) A logged-in parent can see their child's username and code in their own account
- (idea) A parent can reset their child's code themselves, without the admin
- (insight) Constraint: a student cannot register without a parent, so there is always a parent account and parent email to deliver credentials to
- (decision) The admin's view of usernames and codes stays the same
- (idea) The approval email includes a login link that takes them straight to the login page
- (direction) Change: the email with username and code goes to the parent's email at registration, not at approval. Approval sends no credentials; it enables the portal
- (insight) Synthesis, chosen direction: at registration the credentials appear on the confirmation screen and are emailed to the parent with a login link; the student can log in while pending and sees only the pending message; approval enables the portal; the parent can see and reset the child's code from their own account; admin view unchanged; every student has a parent
- (insight) Synthesis, coach connections: (1) with all delivery moved to registration, approval no longer needs to deliver anything, it only unlocks; (2) screen, email and parent account are one idea, the parent as keeper of the child's credentials; (3) after a code reset the screen and email copies are stale, so the parent account view is the only always-current source; (4) open tension: with the email moved to registration, nothing yet tells the family that approval happened
