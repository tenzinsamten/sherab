- (capability) CAP-1 Account & registration — intent: admin creates/verifies teacher accounts and assigns them to classes (many-to-many); students self-register with name+class code, give guardian consent, and land in Pending until a class teacher or admin approves. success: an unapproved student is invisible on any roster/leaderboard and cannot log progress; an approved student appears everywhere and can act.
- (capability) CAP-2 Roster & skill tracking — intent: any teacher assigned to a class can view/edit that class's roster, mark weekly attendance, and set a per-student per-skill-area (language/song/dance) status of Not started/Learning/Confident, with full history retained and optional free-text notes. success: a substitute teacher opens a class they're assigned to and sees complete status history, not just the latest value; a teacher not assigned to a class cannot see it.
- (capability) CAP-3 Homework assignment & tracking — intent: a teacher creates one-off or recurring homework (title, skill area, target students, due date, optional reference links) scoped to their own class; a student sees open homework from their class, opens reference links externally, and self-marks Done; a teacher reviews to Reviewed. success: a recurring assignment auto-generates each period with independent per-instance Done/Reviewed status; overdue+not-Done items stay visible flagged overdue until explicitly archived, never silently expiring.
- (capability) CAP-4 Streaks — intent: the system tracks a per-student streak of consecutive weeks with both attendance and homework Done (Reviewed not required), surviving an admin-configurable number of missed weeks (default 2). success: a student who attends and marks homework Done in week N keeps their streak; missing more than the configured grace window resets it, and changing the grace value requires no code change.
- (capability) CAP-5 Badges — intent: a student earns badges at configurable milestone increments of attendance count and homework-done count, visible only on their own profile. success: crossing a milestone (e.g. 5th class attended) awards the corresponding badge without ranking the student against peers.
- (capability) CAP-6 Team leaderboard — intent: students belong to a fixed-for-the-year team (manually assigned by their teacher at approval/onboarding time, including mid-year joins), and teams are ranked by a combined-streak metric, visible only within the school. success: the leaderboard reflects team standings by combined streak and never triggers automatic reassignment or public exposure.
- (capability) CAP-7 Admin oversight — intent: the admin manages teacher accounts and class assignments, acts as backup approver for any class's pending student registrations, holds the only cross-class view (all teachers, students, overall homework completion), and reviews/actions data deletion requests. success: the admin can approve/reject a registration for any class and see aggregate completion across all classes; no other role has cross-class visibility.
- (capability) CAP-8 Data privacy & deletion — intent: a student can submit a data deletion request from within the app; the admin reviews and must explicitly approve before any of that student's profile, progress, or homework records are erased. success: no deletion occurs without a recorded admin approval step, and once approved all of that student's records are gone.
- (constraint) Teachers are created and verified admin-side only — no teacher self-registration.
- (constraint) Student registration requires guardian consent capture and Pending-state gating before any visibility or activity — guards against dummy/duplicate sign-ups.
- (constraint) Class-scoped visibility, not teacher-owned: all teachers assigned to a class share full view/edit of that class's roster and homework; a teacher sees nothing for classes they're not assigned to.
- (constraint) Skill-status changes must retain full history, not just current value, so a substitute teacher has continuity.
- (constraint) Homework Done (self-report) alone is sufficient to count toward a streak; Reviewed is a separate teacher-confirmed state tracked for skill-mastery history and does not gate the streak.
- (constraint) Overdue, not-Done assignments never auto-expire — they stay visible flagged overdue until a teacher explicitly archives them.
- (constraint) Streak grace period (default 2 missed weeks) must be an admin-configurable value, not hardcoded.
- (constraint) Homework look-ahead window (default: current + next week) must be configurable in the data model without a structural change.
- (constraint) Leaderboard teams are fixed for the school year and manually assigned by teachers — no auto-balancing or randomization, including for mid-year joins.
- (constraint) Minimize personal data collected on minors (nickname + progress only); no public-facing leaderboard or profile.
- (constraint) Data deletion is never automatic — requires an explicit, recorded admin approval step before any erasure.
- (constraint) UI must support German, English, and Tibetan.
- (constraint) Must run as a low/near-free-cost PWA usable on existing family phones/tablets, no app-store install required.
- (constraint) Must tolerate two teachers editing the same class concurrently without clobbering each other's updates.
- (non-goal) Parent-facing login/view is deferred to a future phase — v1 has no separate parent account.
- (non-goal) A structured Duolingo-style curriculum engine (lesson sequencing, spaced repetition, adaptive difficulty, speech recognition) is out of scope for v1; only plain outbound reference links are in scope.
- (non-goal) No embedded in-app media player/preview for reference links in v1 — links open externally as plain 'Open reference' actions.
- (non-goal) Photo/audio proof-of-completion attachments are a possible future option, not v1 — homework completion is self-reported only.
- (non-goal) Offline queueing/sync is a nice-to-have, not day-one scope.
- (non-goal) A public/marketing website or video-lesson platform for the school is out of scope.
- (decision) Success signal: v1 ships directly to the school's own teachers (no separate requirements-gathering round) and is validated by one real Sunday-session end-to-end run — admin onboards a teacher, a teacher approves a pending student, marks attendance, assigns one-off and recurring homework with a reference link, the student marks it done, the teacher reviews it, and streak/badge/team-leaderboard reflect it correctly — then iterates from real teacher feedback.
