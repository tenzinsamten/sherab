- (direction) Source: parent members asked for a message board where posts are visible to everyone (user, 2026-10-31). Guided via scoping questions.
- (decision) Readers: every signed-in, approved user of any role, students included.
- (decision) Posters: admins, teachers, and parents an admin has granted posting; students never post.
- (decision) Scope: one school-wide board; no per-class boards.
- (decision) Moderation: posts appear immediately; authors edit/delete their own; admins and teachers delete any post.
- (decision) Only admins grant or revoke a parent's posting right (on the admin parents area).
- (decision) Extras in v1: push notification on new post, file attachments. Replies and pinning not chosen.
- (decision) Push goes to every subscribed browser, students included, except the author's own.
- (decision) Attachments reuse homework-file rules: PDF only, 5 MB each, at most 2 per post (src/lib/homework-files.ts).
- (capability) CAP-1 Read the board: any approved signed-in user sees posts newest first with author name, time, body, attachments.
- (capability) CAP-2 Post: admins, teachers and granted parents create a post (text plus up to 2 PDFs); others get no form and the DB refuses them.
- (capability) CAP-3 Edit/delete: author edits or deletes own post; admins and teachers delete any post; a deleted post and its files are gone for all.
- (capability) CAP-4 Grant posting: an admin turns posting on/off per approved parent; revoking stops new posts, keeps old ones.
- (capability) CAP-5 Push: a new post sends one push to every subscribed browser except the author's, opening the board.
- (constraint) RLS is the barrier for read, insert, update, delete and storage; UI gating is cosmetic.
- (constraint) Hand-maintain database.types.ts; never regenerate. New migration from 0061.
- (constraint) All UI text in en, de, bo messages.
- (constraint) Push stays off without VAPID vars and respects the Cloudflare 50-subrequest limit (batching as homework push).
- (assumption) A parent's posting right stops working when the parent is no longer approved, since is_parent() requires approval.
- (assumption) Editing a post sends no new push.
- (assumption) Board is a top-level route linked from every role's navigation.
- (assumption) Pending or rejected users cannot read the board.
- (assumption) Body uses the existing rich-text editor and limits from homework, for consistency.
- (question) Should posts expire or be archived after some time, or stay forever?
- (question) Can teachers edit others' posts, or only delete them? (spec says delete only)
- (note) Brownfield: no board/announcement table or route exists; files via pdf-files.ts helpers; push via push.ts + push_subscriptions (0037).
- (event) Self-validate pass 1 (coherence): pass. 5 CAPs each with intent+success; constraints bend design; 5 non-goals; testable success signal.
- (event) Self-validate pass 2 (preservation): pass. All user answers (audience, scope, moderation, extras, grant owner, push audience, attachment rules) landed in SPEC.md; no wrapper-only content.
- (decision) Posts stay forever: no expiry or archive (user, resolves open question).
- (decision) Admins and teachers can only delete others' posts, never edit them (user, resolves open question).
- (direction) User asked to break the spec into stories.
- (decision) Story 1: Database and RLS (posts, files, bucket, parent grant, RLS tests CAP-1..4).
- (decision) Story 2: Admin posting grant on /admin/parents (CAP-4).
- (decision) Story 3: Board page read and post, text only, nav link for every role (CAP-1, CAP-2).
- (decision) Story 4: PDF attachments on posts (CAP-2 files).
- (decision) Story 5: Edit and delete with file cleanup (CAP-3).
- (decision) Story 6: Push on new post (CAP-5).
- (decision) User chose no spec checkpoints and no done checkpoints for any story.
- (event) stories.yaml check: valid. 6 stories, quoted unique prefix-free ids, required fields present, no status field.
- (event) Spec updated: open questions resolved (posts permanent; moderators delete only); added to Non-goals.

- (decision) Board list shows title plus a clipped text preview; clicking expands the full post in place like LinkedIn, no details page (user, 2026-10-31).
- (decision) Posts have a required title (max 120); authors whose stored name is the email show as Sherab Admin (admin) or Teacher (user, 2026-10-31).
