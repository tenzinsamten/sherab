- (note) One /admin/parents load stalled 12.4 s (2026-10-17 05:00:04 UTC); the click 3.5 s later was blocked 8.8 s behind that hover preload
- (note) DB review: indexes adequate; RLS helpers SECURITY DEFINER STABLE but called per row and auth.uid() not wrapped; cost is serial round trips, not query bodies
- (decision) Browser-side suspects #104c-f are out of scope: the HAR shows no growth, so they are unconfirmed
- (capability) CAP-1 A navigation verifies the signed-in user with at most one Auth check per request, and none over the network when local JWT verification is available (#104a, review 1)
- (capability) CAP-2 A click is never held behind a stuck preload, and a Supabase call that does not answer fails within a bounded time instead of hanging (#104g, review 2-3)
- (capability) CAP-3 The root layout load runs its independent queries in one concurrent batch and fetches only the profile columns it uses (#104b, review 6)
- (capability) CAP-4 The student and parent calendar load in no more serial database round trips than the admin and teacher calendar (#104h, review 4)
- (capability) CAP-5 /admin/parents lists every parent's children regardless of parent count, in one round trip (review 7, latent URL-length bug)
- (capability) CAP-6 RLS policies on the hot tables evaluate auth.uid() and the role helpers once per query, not per row (#104h, review 5)
- (constraint) Access semantics must not change: same rows visible to the same roles before and after; existing RLS tests pass unchanged
- (constraint) safeGetSession keeps its { session, user } return shape for its 78 callers
- (constraint) RLS change ships as a new migration file; past migrations are not edited
- (constraint) Runtime is Cloudflare Workers: no Node-only APIs; JWKS fetch must be cached per isolate
- (constraint) Verification per project rule: DB reset, then test, check and build exit 0 before any commit; database.types.ts stays hand-maintained
