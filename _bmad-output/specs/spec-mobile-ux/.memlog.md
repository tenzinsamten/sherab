- (direction) User: most parents, students and teachers use phones or iPads; only admins use laptops; need better mobile UI/UX.
- (direction) User pain points: overall look (feels desktop), navigation, tables and lists, forms and dialogs — all four.
- (decision) Cover phone (<768px) and tablet (768-1279px) explicitly, not phone-only; user choice.
- (constraint) Stay within Siemens iX components plus custom CSS; no replacement UI library; user choice.
- (decision) Express mode chosen by user; gaps become open questions.
- (capability) CAP-1 Thumb-reachable primary navigation on phone/tablet for parent, student, teacher instead of hamburger-only access below lg.
- (capability) CAP-2 Lists and tables readable on phone without horizontal scroll (stacked rows/cards).
- (capability) CAP-3 Forms and dialogs usable one-handed on phone: full-width fields, 44px+ targets, dialogs fit viewport, primary action reachable.
- (capability) CAP-4 Tablet layout uses the width (two-column/grid where content allows) instead of a stretched phone column.
- (capability) CAP-5 Mobile visual polish: consistent spacing, type scale and card surfaces so role pages feel like an app, not a desktop dashboard.
- (capability) CAP-6 Phone header holds only essentials; language and account stay reachable without overflow hunting.
- (constraint) Admin desktop experience stays as is; admin routes out of scope, and shared components must not regress on desktop.
- (constraint) All three locales (en, de, bo) must fit — Tibetan script and longer German labels cannot truncate key labels.
- (constraint) No feature, data or permission changes; presentation only.
- (constraint) Existing PWA, page tours (#101) and help overlay keep working; tours target elements visible on mobile.
- (assumption) Breakpoints: phone <48em (768px), tablet 48em-80em, desktop >=80.0625em (iX lg) — aligned to iX and existing WIDE_SCREEN_QUERY.
- (assumption) Existing brand tokens (design-tokens.md, brand-guide.md) remain the visual source; this spec does not rebrand.
- (question) iX has no bottom-nav component — is a custom-CSS bottom bar built from iX icons/buttons acceptable under the stay-within-iX constraint?
- (question) Which 4-5 destinations go in each role's primary nav (teacher has Dashboard, Calendar, Requests, Leaderboard; where do class pages sit)?
- (question) Which iPhone/iPad models and OS versions must be supported (oldest Safari)?
- (question) Should landscape phone be supported or portrait only?
