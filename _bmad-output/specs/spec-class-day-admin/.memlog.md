- (direction) User (#105) wants the admin to view a class day, edit it and add new ones; guided questions asked since input was sparse; slug class-day-admin
- (note) Existing (ef6c387): admin Add days (date range, ?/addClassDays), day view from the month grid, Cancel/Restore day (?/setClassDayCancelled); class_days holds only day (unique) and cancelled
- (note) User confirmed the existing controls show in production for the admin; not a visibility bug
- (decision) View stays the month grid (clicking a date opens the day); no list view
- (decision) Edit means: keep cancel/restore, add move to another date and delete
- (note) FKs: class_sessions.class_day_id CASCADE; attendance_records -> class_sessions RESTRICT; session_leave_history and sick_leave_decisions -> class_sessions CASCADE; no DELETE policy on class_days; class_days_create_sessions trigger builds sessions on insert from class schedules
- (decision) Delete only when untouched: no attendance, leave answers or sick decisions on any of its sessions; otherwise refused with a pointer to Cancel day
- (decision) Move keeps the same sessions (classes, times, leave answers) on the new date; the target date must have no class day
- (decision) Only future days (after today in Europe/Berlin) may be moved or deleted, and only to a future date; today and past stay fixed so attendance, streaks and badges never shift
- (capability) CAP-1 Admin moves a future class day to a free future date; its sessions and answers follow
- (capability) CAP-2 Admin deletes a future class day that nothing references; otherwise it is refused with a pointer to Cancel day
- (constraint) The move/delete rules (admin, future only, free date, untouched) are enforced in the database, not only in the UI (AD-2)
- (constraint) Actions live in the existing day view opened from the month grid; text localized in en, de and bo
- (decision) Non-goals: no list view, no editing session times here, no notification to parents or teachers about a move, no bulk move or delete, no undo
- (assumption) Admin-only as today; teachers keep editing only their sessions
- (event) Pass 1 coherence: PASS. Two CAPs with testable success; constraints rule options out (UI-only checks, past days, duplicate dates); four non-goals; success signal is demonstrable in production
- (event) Pass 2 preservation: PASS. #105's view/edit/add asks map to the month grid (kept), CAP-1, CAP-2 and the existing Add days; FK and trigger facts in Constraints and the memlog. Wrapper-only content dropped: #105's open-question list, now answered
- (event) Spec created: SPEC.md, 2 capabilities, no companions
